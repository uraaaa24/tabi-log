# 非機能要件

## 決定事項

- 実装はReact Native + Expo + TypeScriptを採用する方針。依存ライブラリはできるだけ増やさず、必要な箇所だけ使う。詳細は[技術構成の検討案](technical-options.md)を参照。
- ストアの開発者登録費などを除き、MVPの月々の維持費は原則ゼロを目指す。定額費用が必要な外部サービスは避けて検討する。
- MVPはiPhoneとAndroidの両方で利用できる。
- 対応OSは採用するExpo SDKが標準で対応する範囲を基本とし、古いOS向けの特別対応は追加しない。利用ライブラリ全体の要件を確認して具体的な最低バージョンを確定する。
- 開発中の動作確認にはiPhone実機とAndroidエミュレーターを使う。公開前にはAndroid実機でも主要操作を確認し、写真の取り込み・記録の保存・指操作を検証する。Android実機の確保方法は未決定。
- MVPの画面はスマートフォンの縦向けに設計する。横向けの専用表示は対象にしない。
- タブレット向けの専用画面はMVPに含めない。
- 画面の表示言語は日本語のみ。
- 通信がない状態でも地図を見られ、訪問記録の閲覧・追加・編集ができる。
- 画面読み上げで訪問状態の切り替えと訪問記録を操作できるようにする。県・国の選択を名前検索で行う従来の方針は撤回し、検索・場所一覧は設けない。地図上の要素を使った読み上げ操作の実現方法と対応範囲は未決定。
- 端末の文字サイズ設定に応じてアプリの文字も拡大し、訪問履歴や日記を読んで操作できる。
- 動作確認の目安は、一人あたり訪問記録が数百件、写真が数千枚。これは保存数の上限ではない。
- 写真の取り込み・記録の保存などの処理中は、アプリ内の画面移動・二重操作・キャンセルを受け付けず、進行状況を表示する。完了または失敗後に操作可能に戻す。OSによる中断・終了への対策は別途必要で、この制御だけで処理完了を保証しない。
- アプリのクラッシュ時に、匿名の診断情報を送信しない。
- 自動テストはデータ保護・整合性に関わる処理を中心に用意する。見た目はStorybook、OS連携・指操作・途中終了からの復旧は実機で確認する。詳細は[技術構成の検討案](technical-options.md)を参照。
- 画面操作などの利用状況の分析データを収集・送信しない。
- 保存した写真は、全画面表示からさらに拡大して見返せる品質を確保する。長辺最大3,072pxを仮の基準とし、それより小さい写真は引き伸ばさない。実装時に実際の写真で拡大表示の品質と保存容量を確認する。保存形式はJPEGに統一し、透明部分がある画像は白背景にする。圧縮率と白背景への具体的な変換方法は実装時に検証する。

## 検討中の事項

- 木目・ピンの質感と、文字・ピンの読みやすさの両立。
- 写真の表示品質と保存容量の目安。
- 数百件の訪問記録・数千枚の写真があるときの表示時間と写真保存処理の許容時間。
- 利用ライブラリ全体を確認した上での、具体的な最低対応OSバージョン。
