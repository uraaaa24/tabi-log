# 訪問記録モデル

## 決定事項

- 記録は場所を中心に扱う。旅行全体を束ねる単位は当面設けない。
- 同じ場所への連続した滞在は、期間を持つ1件の訪問記録にする。
- 例: 長野に11月1日から2日まで滞在した場合、11月1日〜2日の訪問記録を1件作る。
- 同じ場所への別の訪問は、別の訪問記録として扱う。
- 訪問として記録する目安は、観光・食事・用事・宿泊など、利用者が目的を持って立ち寄ったと認識する場所。単なる通過は想定しない。ただし、アプリが訪問の正しさを判定したり、記録を強制したりはしない。
- 訪問先の県・国は利用者が手動で選ぶ。端末の現在地や写真の位置情報から自動では判定しない。
- 記録する場所の単位は、日本国内では都道府県、海外では国とする。海外の都市単位の記録は設けない。
- MVPでは、グアムや香港のような地域を国とは別の訪問先としては扱わない。利用者が195の国から記録先を選び、必要なら日記に地域名を書く。アプリは地域から国への自動対応付けをしない。
- 世界地図で選べる訪問先は、[国連加盟国193とオブザーバー国2](https://research.un.org/en/unmembers/intro)の計195を基準にする。国連M49の「地域」は独立した訪問先としては採用しない。
- 同じ日付に複数の場所の訪問記録を作れる。どの場所を記録するかは利用者が選ぶ。
- 同じ場所でも日付・期間が重なる訪問記録を複数作れる。重複を理由に登録を禁止しない。
- 各場所には「行った／行っていない」の状態を持たせる。地図のピンはこの状態で判定し、訪問記録がなくても「行った」にできる。訪問記録がある場所は「行った」の状態となる。
- 訪問済みの場所でも、訪問日・写真・日記などの記録は任意。記録なしで「行った」として表示できる。
- 訪問記録を追加したときは、その場所を自動で「行った」にする。訪問記録を削除しても「行った」は維持する。
- 「行った」から「行っていない」に戻すとき、その場所に訪問記録があれば、削除される訪問記録の件数と写真枚数を示して確認する。確定すると、その場所のすべての訪問記録と、紐づく写真・日記・交通手段を削除する。
- 訪問記録を作る場合は訪問日を必須とし、複数日にわたる場合は開始日と終了日を入力する。「行った」状態だけなら日付は不要。
- 日付入力は一つの訪問日から始め、複数日の場合だけ終了日を追加する。日帰りで開始日と終了日を二度入力する必要はない。
- 新しい訪問記録の日付の初期値は空欄とし、今日の日付を自動では入力しない。
- 正確な日付が分からない場合、MVPでは日付不明の訪問記録は作らず、「行った」の状態だけを残せる（日付必須の決定に基づく）。
- 訪問日・期間は利用者が入力した現地の暦日をそのまま扱い、アプリ側で時差換算しない。
- 訪問記録に未来の日付は入力できない。期間の終了日は開始日より前にできない。
- 写真は訪問記録に紐づける。同じ場所でも別の機会の訪問（例: 2025年と2026年の長野）は別記録とし、写真も分けて見返せる。
- 写真を追加するときはアプリ内にコピーする。元の写真を端末の写真アプリから削除しても、訪問記録では見返せるようにする。
- 複数写真の取り込みで一部が失敗した場合、成功した写真は編集画面に残し、失敗した写真を利用者に知らせる。訪問記録への反映は「保存」で確定する。
- MVPで取り込む写真は静止画のみとする。Live Photosは静止画として取り込み、動画や動きの再生には対応しない。
- アプリ内の写真は、思い出を見返せる画質で保存する。元画像と同じ画質での再書き出しは要件としない。
- 1件の訪問記録に追加する写真に、小さな固定の枚数上限は設けない。利用可能な端末容量による制約はある。
- 訪問記録内の写真は、アプリに追加した順に表示する。
- 複数日にわたる訪問でも写真は日別に分けず、その訪問記録の一つの写真一覧にまとめる。
- 日記・メモは訪問記録ごとに自由文を1つ持つ。複数日の訪問でも日別には分けない。
- 日記・メモは通常の文章と改行のみとし、太字や見出しなどの装飾機能は設けない。
- 日記・メモには短い固定文字数上限を設けない。複数日の思い出を一つの文章として残せるようにする。
- 訪問記録のタイトル欄はMVPでは設けない。場所・訪問期間・写真サムネイルで記録を見分ける。
- 市町村や観光地名の専用欄はMVPでは設けない。必要なら利用者が日記・メモに書く。
- 交通手段は、その場所へ行くときに使った手段として訪問記録に紐づける。滞在中の移動は対象にしない。
- 1件の訪問記録に複数の交通手段を選択できる。
- 交通手段は候補から複数選択し、候補にないものは「その他」として自由入力できる。
- MVPの交通手段候補は、車・電車・新幹線・飛行機・バス・船・徒歩・自転車・その他とする。
- 訪問記録では日付・期間のみ必須で、写真・日記・交通手段は任意入力とする。
- 写真へのアクセスを許可しなくても、日付・日記・交通手段で訪問記録を作れる。
- 訪問記録の保存後も、日付・期間、日記・メモ、交通手段、写真をすべて編集できる。
- 訪問記録の入力・編集内容は「保存」ボタンで確定する。未保存の変更がある状態で画面を離れる場合は確認を表示する。
- 未保存で画面を離れる際の確認は、「変更を破棄して戻る」「編集を続ける」の二択とする。確認画面内に保存操作は設けない。
- MVPでは未保存の下書きを保持・復元しない。アプリ終了時には未保存の入力を失う場合があるが、保存済みの記録は維持する。
- 訪問記録の場所は、地図から選んだ県・国に固定する。入力・編集画面に場所の変更欄を設けず、別の場所への記録の移動はMVPに含めない。従来の場所変更可という方針を撤回する。誤った場所に登録した場合は、その記録を削除し、地図から正しい場所を選んで作り直す。写真の再選択・日記等の再入力が必要で、記録の複製・移動機能は設けない。削除しても元の場所のピンは残るため、必要なら利用者が別途外す。
- 写真は訪問記録から1枚ずつ削除できる。写真を削除しても訪問記録自体は残す。
- 保存済みの記録への写真の追加・削除は、その記録の編集画面からのみ行う。アルバム・写真一覧・写真の全画面表示には写真の削除操作を設けない。
- 写真を削除する前に確認を表示する。
- 編集中の写真の削除は「保存」で確定する。編集を取り消した場合、削除しようとした写真も元の状態に戻す。
- 訪問記録は1件ずつ削除できる。削除した訪問に紐づく写真・日記・交通手段も削除するが、その場所のピンと他の訪問記録は残す。
- 訪問記録を削除する前に確認を表示する。削除の入口は既存記録の編集画面の末尾にまとめ、アルバム・訪問履歴には置かない。新規登録画面には表示しない。

## 検討中の事項

- 国連基準の195に入らない場所は、独立した訪問先として選べない。具体例と案内文言をどう示すか。
