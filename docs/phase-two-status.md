# Phase2：日本の記録と振り返り

## 実装範囲

段階2の中心となる「日本地図で場所を選ぶ → 記録する → アルバムで振り返る」を実装。世界地図、初回チュートリアル、質感の最終調整と公開前の実機受け入れは後続段階。MVP全体の完成・ストア公開準備完了を意味しない。

- 47都道府県のオフラインSVG地図、指の位置を基準にした連続ピンチ（1〜6倍）・1本指パン、訪問済みのピン。無地の濃い茶色のボードに薄い木色の地形を載せ、木のボード感を配色で保つ。地名・拡縮ボタン・木目模様は表示しない。地図の倍率と位置は画面がマウントされている間保持する。
- 県選択から記録がなければ入力、あれば最新のアルバムへ直行する。過去の訪問はアルバム内のシートで開始日・作成日時・IDの降順に切り替える。ピンだけの登録は新規入力画面の補助操作。設定画面に地図の出典・利用条件を移した。
- 場所固定の新規登録・編集。初期日付は空欄、OS日付選択、複数日、自由文の日記、9種類の複数選択交通手段、その他の自由入力。現地暦日の検証と未来日・逆転の拒否。
- 保存でのみ確定。未保存離脱は破棄／編集継続の二択。失敗時は入力を保持。保存・写真取り込み中はモーダルと戻る操作の抑止で二重操作と画面移動を防止する。
- 静止画の複数取り込み、一部失敗時は成功分を編集に保持。保存前の追加写真は一時領域に置き、削除操作も保存するまで既存ファイルを消さない。
- 写真本体JPEG長辺最大3,072px・品質0.88、サムネイル長辺最大480px・品質0.8。小さい写真を拡大しない。ID・回転・幅の特性を保持する。
- 閲覧アルバムは先頭2枚と入力された日記・交通手段を表示。写真3枚以上では写真一覧へ。FlashList 2.3.2 のmasonry、2列、`optimizeItemArrangement=false`。セル内の幅・傾きを変え、追加順と縦横比を維持し、削除後は残りを詰める。
- 全画面表示は左右スワイプ、最大5倍のピンチ拡大、2本指の移動。編集画面にのみ写真削除と訪問削除を置く。
- 訪問削除でピンを残す。未訪問へ戻す際は記録件数・写真枚数と日記も消えることを確認し、その県の関連記録だけを削除する。

## 保存と回復

`expo-sqlite` 58.0.15、`expo-file-system` 58.0.13、`expo-image-manipulator` 58.0.16、`expo-image-picker` 58.0.10、OS日付選択9.2.1、FlashList 2.3.2、UUID生成用`expo-crypto` 58.0.7をSDK 58の対応表に合わせ直接固定した。ORMやサーバーは追加していない。

SQLiteの基本接続の外部キーを有効にし、WAL・schema version 1を使う。新しい形式のDBを古いアプリで書き換えることは拒否する。訪問・写真メタデータ・交通手段・ピンの更新は排他トランザクション。排他接続では外部キー設定の継承に頼らず、場所の存在検査と未訪問化の関連行削除を明示する。場所と作成日時は編集で変更しない。

画像はDBに相対パスを記録する。保存時は一時領域から永続領域の `.pending` ファイルへコピーし、コピー成功後に最終名へ移す。DB確定前に既存写真を削除しない。DB失敗時は入力と一時写真が残り、同じIDで再試行できる。DB確定後と次回起動時にDB非参照画像だけを回収する。回収失敗は保存成功を取り消さず、次回起動で再試行する。DBが読めない場合は写真回収も行わない。未保存下書きの復元はしない。

透明画像のJPEG変換は、採用版の標準APIではネイティブの背景色を指定できないため、`patches/expo-image-manipulator@58.0.16.patch` でiOS/AndroidのJPEG出力だけを白背景に合成する。PNG/WebP出力は変更しない。pnpmの固定パッチとしてfresh installに適用する。ネイティブの再ビルドが必要で、実際の透明PNG・HEIC・Live Photosの変換品質とiOSコンパイルは実機確認を残す。

地図の出典・利用条件と再生成は[地図データ](map-data.md)を参照。地図ライブラリ選定とFlashList採用は今回のユーザー確認に基づく。

## 検証記録

Expo SDK 58への更新を追加した。現在の版と更新時の確認は[開発手順](development.md#sdk-58への更新)を参照。SDK 58更新コミットのQuality（run 42366511910）とAndroid（run 42366511880）は成功。以下の初回PRのCI結果はSDK 57での記録として保持する。

2026-11-07、Codex cloudのLinuxで実行。SDK 58更新後のローカル最終確認は19ファイル・189テスト成功。PRのCI結果はPR上で別に確認する。

- `pnpm check`：Lint・整形・型・Vitest・依存方向。SQLiteの実SQLをNode SQLiteで実行し、保存・ロールバック・並び順・関連削除・場所固定を検査。これはexpo-sqliteの実機実行とは区別する。
- 写真ファイルのテスト：部分コピー失敗からの再試行、編集破棄、DBを基準にした回収、DB読み込み失敗時の保護。ファイルAPIの代替実装を使い、OS連携の検証とは区別する。
- `expo prebuild --no-install --platform all`：iOS/Androidのネイティブプロジェクト生成に成功。カメラ・マイク権限の除去設定を生成されたAndroid manifestでも確認。ネイティブバイナリのビルドとは異なる。
- ブラウザStorybook：日本地図、スクラップ写真、縦横混在・2,000枚のFlashListを実際に表示して確認。47県の存在、長野県タップでJP-20を選択、CDPの2点タッチによるピンチ途中の倍率変化・1本指パン・縮小による全体復帰、フォームのメモ入力と交通手段選択、訪問切り替えシートを確認。2,000枚のうち18セルの描画、画像の重なりなし、最終写真へのスクロール到達、実行時エラーなしをPlaywrightとChromiumで確認した。日付選択ダイアログはブラウザ用Storybook内だけ案内表示に差し替え、OSの確認は実機に残す。大量データの例は生成し、リポジトリへ大量の画像を追加しない。
- `pnpm check:native-bundles`：初回CIでネイティブStorybook登録ファイルが未生成のままMetroが走査し、解決に失敗したため、コマンド先頭で明示生成するよう修正。生成物を削除し、`CI=1 pnpm check:native-bundles`で両OS・両モードの成功を確認した。iOS/Androidの製品・ネイティブStorybookのJSエクスポートと入口分離。モード切替時のMetroキャッシュ混在を避け、各エクスポートで`--clear`する。
- Android CIの起動画面検査を、製品では日本地図の文字と無地の木色の背景・地形の画素、Storybookでは従来のPaperCardの文字・紙色・Lucideの画素を検査するよう更新した。[初回PRのAndroid CI（run 7）](https://github.com/uraaaa24/tabi-log/actions/runs/42353310138)でDevelopment Buildのコンパイルとエミュレーター上の両起動画面検査に成功。訪問保存・写真取り込みなどの受け入れ確認は含まない。

## 実機での受け入れ確認（未実施）

このクラウドにはXcode、Android SDK・エミュレーターがない。静的検証やブラウザの成功を以下の確認済みとは扱わない。

1. 新しいDevelopment Buildで、機内モード中に県選択→日付のみの保存→写真・日記・交通手段の編集→アルバム→アプリ再起動後の保持を確認する。
2. iOSのOS日付入力、Androidの戻る操作、未保存破棄、保存・取り込み中の操作抑止、失敗通知と再試行を確認する。
3. 写真ライブラリのアクセス拒否、元画像削除後の表示、縦横・HEIC・Live Photos・透明画像、長文・大きい文字サイズを確認する。
4. 容量不足、コピー・DB確定・不要画像回収の各時点での強制終了、再起動、再試行で保存済みの思い出が失われないことを確認する。
5. 写真全画面のピンチ・2本指移動・左右スワイプ、地図の小さな県の選択、読み上げで県・記録に到達できることを確認する。
6. 数百件・数千枚で実機の描画時間・メモリ・取り込み容量を計測する。セル内可変幅の現在案が自然なスクラップ配置として十分かも評価し、段階4で仕上げる。

レビュー・マージは人が担当する。Android CIの成功だけでiPhone・Android実機や公開前の受け入れを完了とは扱わない。
