# ブラウザE2Eテスト

## 目的と位置づけ

製品と同じ画面・Expo Routerの遷移・SQLite（expo-sqliteのWeb版wa-sqlite）をChromiumで動かし、Playwrightで「地図で選ぶ → 記録する → アルバムで振り返る」と編集・写真・削除・ピン・未保存時の離脱を利用者の操作として検証する。ユーザーの依頼でPlaywrightを採用した。製品のWeb対応ではなく、E2E専用のビルドとして扱う。

`pnpm test:e2e` でE2E用のWebビルド（`pnpm build:e2e`、`dist/e2e-web`）を作り、`e2e/*.spec.ts` を実行する。CIの `e2e` ジョブも同じコマンドを使う。`pnpm check` には含めない（ビルドに約1分かかるため）。

## テストの書き方

『単体テストの考え方/使い方』の原則に従う。

- 観察できる振る舞いを検証する。操作・確認は役割・アクセシビリティラベル・表示文言で行い、コンポーネントの内部・テストIDに依存しない。画面を作り替えても振る舞いが同じならテストは壊れない。
- 1テスト1シナリオ。準備・実行・確認（AAA）を空行で区切り、テスト名に利用者から見た振る舞いを書く。
- 管理下の依存（SQLite）は本物を使う。差し替えるのは、ブラウザに実装がないOSの機能だけにする（下記）。
- E2Eは時間がかかり壊れやすいので、主要な流れと画面でしか確かめられない振る舞いに絞る。日付判定・保存の巻き戻し・写真ファイルの回収などの細かい分岐は、`src/` のVitestで検証する。
- 各テストは新しいブラウザコンテキストで始まり、記録・写真は残らない。「今日」は2026-05-20（Asia/Tokyo）に固定する。
- 保存の完了は、アルバムにしかない要素（訪問履歴の切り替え）で確認する。日記などの文言は編集画面の入力欄にも現れるため、保存完了の根拠にしない。

## E2E用の差し替え

`TABI_E2E=1` かつ `platform === 'web'` のときだけ、`metro.config.cjs` が `e2e/platform/` に解決を差し替える。iOS/Androidのビルドでこの環境変数を使うとMetroがエラーにする。製品バンドルへ混入しないことは `pnpm check:native-bundles` で確認する。

| 対象                                     | 差し替え                                                                                                                                                        | 実機との違い                                                    |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `expo-sqlite`                            | 本物のWeb版を使い、未対応の `withExclusiveTransactionAsync` だけを再現。別接続と同様に外部キーOFF、実行中は元の接続からの書き込みを `database is locked` で拒否 | 元の接続から未確定の行が読める（実機のWALでは確定済みのみ）     |
| `expo-file-system`                       | 実機と同じ非同期コピー・移動、既存ファイルへのコピー失敗、存在しない対象の削除失敗を再現。内容はdata URIで `localStorage` に保持し、再読み込み後も残る          | 容量不足・権限・強制終了時の部分書き込みは再現しない            |
| React NativeのAlert                      | react-native-webのAlertは何もしないため、同じタイトル・本文・ボタンのダイアログを表示                                                                           | OSのダイアログの見た目・Androidの戻る操作での閉じ方は確認しない |
| `@react-native-community/datetimepicker` | Androidのダイアログと同じく、OKで `set`、キャンセルで `dismissed` を返す。`maximumDate` より後は選べない                                                        | iOSのスピナー表示は確認しない                                   |

写真の選択・縮小・サムネイル生成は、expo-image-picker・expo-image-manipulatorのWeb実装をそのまま使う。写真はテスト内でPNGを生成し、ブラウザのファイル選択に渡す。

## 確認していないこと

ブラウザでの成功を、iPhone・Androidでの動作確認とはみなさない。次は実機で確認する（[Phase2の記録](phase-two-status.md#実機での受け入れ確認未実施)）。

- ネイティブのSQLite・ファイル保存・強制終了からの復旧、容量不足
- OSの写真選択・権限・HEIC・Live Photos、OSの日付選択・確認ダイアログ
- 地図・写真のピンチ・パンなどのジェスチャー、Androidの戻るボタン、読み上げ
- 実機での描画性能・メモリ
